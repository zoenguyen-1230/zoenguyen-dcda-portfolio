Experiment A: Portfolio Enhancement

For Experiment A, I used Claude Opus 4.5 as a coding collaborator inside VS Code to build a responsive image carousel for my portfolio. The carousel displays photos of my friends and me at TCU to highlight my campus experience. The feature includes next/previous buttons, dot navigation, keyboard arrow support, and accessible alt text.

I started with a broad “build a carousel” prompt, then refined it through debugging. The first version overflowed its container and only displayed the first image. I worked with Claude to adjust the CSS while I also manually corrected image filenames/paths and rewrote alt text so it matched my actual photos. After several rounds of feedback and testing, I successfully implemented a fully functional carousel that enhances the visual appeal and user experience of my portfolio. The final code is clean, well-commented, and adheres to best practices for responsive design and accessibility.

Vibe Coding Guidelines/Reflection

When I used AI for vibe coding, I try to treat it as a collaborator rather than an autopilot. I start by planning the feature first and listing the exact behaviors and constraints I want, so my prompt is specific enough and make room for less errors. After the AI generates code, I read through every section before running it, and I test it section by section so I can see which changes actually affect the result. I use an “understanding spectrum” in my comments to honestly mark what I fully understand, what I understand at a logic level, and what I still find unclear. When something breaks, I debug step by step, from checking file paths, layout rules, to data flow, instead of assuming the whole solution is wrong. I also make content-level corrections myself, such as updating image names, paths, and alt text, to ensure accuracy and accessibility. Overall, my guideline is to let AI build the foundation of the code, but keep responsibility for verification, clarity, and final decisions to myself.

Experiment B: Python Code Generation

San Francisco Restaurant Inspection Scores Map

For Experiment B, I used Gemini 2.5 Flash feature within Google Colab to create an interactive map visualization of San Francisco restaurant inspection scores. I got the dataset from the City of San Francisco profile on Kaggle. The map displays inspection data from the SF Department of Public Health, showing restaurant locations color-coded by their health inspection scores.

I worked with Gemini to generate Python code using Folium and Pandas for data processing. The visualization includes marker clustering for better performance with large datasets and a heat map layer to show the geographic distribution of inspection scores across the city.

Interactive Map

Explore the map below to see restaurant inspection scores across San Francisco. Click on markers to view restaurant details and their inspection scores:

Documentation

The map was generated using Python with the Folium library. Key features include:

  • Marker Clustering: Groups nearby restaurants for cleaner visualization at lower zoom levels
  • Heat Map Layer: Shows density and distribution of inspection scores
  • Color-Coded Markers: Visual indication of inspection score quality
  • Interactive Popups: Click markers to see restaurant name, address, and inspection score

The data comes from the San Francisco Department of Public Health's restaurant inspection database, which is publicly available through the city's open data portal.
